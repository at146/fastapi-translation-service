Прочитал все диффы. Вот ревью по убыванию серьёзности.

## Серьёзные замечания

**1. Плейсхолдеры `__TAG1__` могут не пережить токенизацию MarianMT** — `app/tag_handler.py:54`

MarianMT использует SentencePiece. `__TAG1__` почти наверняка будет разбит на subword-токены (`__`, `TAG`, `1`, `__`), и модель не обязана их сохранить в выходе как непрерывную последовательность. Это объясняет, зачем у вас в `_normalize_placeholders` несколько форматов (`{TAG1}`, `[TAG1]`, `<TAG1>`) — модель уже их искажает.

Решение: либо добавить плейсхолдеры как special tokens (`tokenizer.add_special_tokens({"additional_special_tokens": [...]})` + `model.resize_token_embeddings`), либо использовать символ, который точно не расщепится (типа `⟦1⟧` с unicode-скобками). Без этого вы постоянно будете попадать в fallback-ветки.

**2. `_validate_tag_structure` ложно срабатывает на обычные тексты** — `app/tag_handler.py:386-397`

`ET.fromstring(f"<root>{text}</root>")` упадёт, если в переводе есть необработанный `&` (амперсанд в обычном тексте — частое явление, например `R&D`, `Tom & Jerry`). Это запустит `_fix_tag_order`, который сделает только хуже — он стирает все теги и расставляет их заново по относительным позициям из `source_text`.

Решение: либо escape `&` перед валидацией (`re.sub(r"&(?![a-z]+;|#\d+;)", "&amp;", text)`), либо валидировать только сами теги (баланс пар), не парся весь текст как XML.

**3. После `_fix_tag_order` нет повторной валидации** — `app/tag_handler.py:212-213`

```
warnings.append("Нарушена структура тегов, попытка исправления")
result = self._fix_tag_order(result, mappings, source_text)
```

Если `_fix_tag_order` тоже произвёл невалидный XML — мы это никак не проверяем и возвращаем `success=True`. В memoQ это попадёт сломанным сегментом. Стоит после fix снова прогнать валидацию и при провале уйти в `used_fallback=True`.

**4. `mqxliff_insert_csv_translation_xmlsafe_v3.py` в корне репо**

Это самостоятельный CLI-скрипт на 446 строк, никак не связанный с FastAPI-сервисом (`app/`). Вопросы:
- Это вообще должно быть в этом репозитории? Если это разовый tool для офлайн-обработки — лучше отдельный репо/папка `scripts/`.
- Имя `_v3` подсказывает, что есть `v1`, `v2` где-то ещё — это типично «code rot».
- Использует `Dict`, `List`, `Tuple` из `typing` при `target-version = "py310"` — ruff (UP) должен ругаться, либо файл исключён (?).
- Дублирует логику плейсхолдеров (`PLACEHOLDER_RE`, `placeholder_aliases`) с `app/tag_handler.py`. Хорошо бы общий код вынести.

**5. `_has_minimum_tags` принимает потерю 50% тегов** — `app/tag_handler.py:422`

Для XLIFF/memoQ потеря даже одного тега ломает сегмент. Порог 50% слишком мягкий для production — лучше требовать ≥100%, либо вообще убрать порог и ориентироваться на success/fail после `_insert_missing_tags`.

## Помельче

**6. KeyError при невалидном payload** — `app/__main__.py:70`

```python
user_messages = [m["content"] for m in data.get("messages", []) if m["role"] == "user"]
```
Если в `messages` элемент без `role` или без `content` — 500 вместо 400/422. Добавьте `m.get("role") == "user"` и `m.get("content", "")`.

**7. `_fix_tag_order` теряет точные позиции для одинаковых тегов** — `app/tag_handler.py:362-366`

`search_start` индексируется по полной строке тега (`<g id="1">`). Для не-уникальных id (или для повторяющихся `<x/>` без id) счётчики будут перезатираться. На практике XLIFF id обычно уникальны, но самозакрывающиеся теги без id — частый случай.

**8. Закомментированные роуты в `app/__main__.py:149-177`**

Мёртвый код. CLAUDE.md явно говорит «единственный endpoint» — удалите.

**9. `.vscode/settings.json` под git**

Обычно это личные настройки и они в `.gitignore`. Если для проекта нужны единые pytest-настройки, лучше положить их в `pyproject.toml` (там уже есть `[tool.pytest.ini_options]`) — pytest всё равно будет их подхватывать.

**10. Тесты используют `print(...)` с `noqa: T201`** — `tests/test_tag_handler.py`

Для pytest это лишнее: `-v` и так показывает имена тестов. Если нужен детальный output — лучше через `caplog` или просто оставить только assert-ы. Сейчас тесты выглядят полу-как-script, полу-как-pytest.

**11. Не покрыты тестами**

- `_fix_tag_order` (самая сложная функция);
- валидный XML с `&` в переводе (см. п.2);
- порядок тегов нарушен (модель переставила `__TAG2__` перед `__TAG1__`);
- больше плейсхолдеров в переводе, чем было в исходнике (галлюцинация модели).
